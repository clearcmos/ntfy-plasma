# ntfy-plasma

KDE Plasma 6 widget (plasmoid) that streams ntfy topics into a panel popup and a top-centre overlay. Pure QML and JS on top of the system's Qt 6 and Plasma; no build step, no package manager. README.md has the user-facing overview and the file layout.

## Commands

```bash
make check          # lint + format-check + test; exactly what CI runs
make lint           # scripts/lint-qml.sh, shellcheck, bash -n, py_compile, actionlint
make format         # qmlformat -i over package/ and tests/
make format-check
make test           # tests/run.sh
./install.sh        # symlink package/ into ~/.local/share/plasma/plasmoids/
kquitapp6 plasmashell && kstart plasmashell   # reload after QML edits
```

The Qt 6 tools live in `/usr/lib/qt6/bin` (`QT_BIN` overrides it). The `qmllint` on Arch's PATH is Qt 5's and accepts broken files, so never call it bare.

## Structure

- `package/contents/ui/main.qml`: PlasmoidItem root. Wiring only; it loads only inside plasmashell, so its logic lives in `Feed.js`.
- `package/contents/ui/Feed.js`: pure helpers (topic parsing, stream URL, line splitting, feed dedupe and cap). Put new non-view logic here so it stays testable.
- `package/contents/ui/NtfyClient.qml`: XHR streaming client with capped backoff.
- `package/contents/ui/{MessageDelegate,OverlayPopup,EdgeFlash,ConfigGeneral}.qml`: views.
- `package/contents/ui/Emoji.js`: generated by `scripts/regen-emoji.sh`; do not edit by hand.
- `tests/`: `tst_*.qml` run by `qmltestrunner` headless; `fake_ntfy.py` serves the live client test on port 38417; `test_*.sh` cover the shell scripts; `fixtures/lint/` holds known-good and known-bad lint inputs.

## Conventions

- Files that declare delegates or inline components use `pragma ComponentBehavior: Bound`; delegates declare `required property` for model roles. Qualify parent-scope names (`root.msg`, not `msg`). `scripts/lint-qml.sh` fails on any qmllint warning except unqualified `i18n`/`i18nc`/`i18np`/`i18ncp`, which Plasma injects through the applet context.
- `qmlformat` is the formatter, with its defaults and no column limit. It rewrites a few things badly, so write around them: multi-branch bindings as `{ if (...) return ...; }` blocks rather than nested ternaries; comments on their own line above an unbraced `if`; `String.fromCharCode` rather than `\u` escapes in string literals (it decodes escapes into literal characters).
- No emoji or em dash characters in source; tests build them with `String.fromCodePoint` / `String.fromCharCode`.
- Every module in `package/contents/ui/` needs `tests/tst_<name>*.qml`, and every script needs `tests/test_<name>.sh`; `tests/run.sh` enforces it. Exempt: `main.qml` (needs plasmashell) and `scripts/regen-emoji.sh` (network-bound; its output is reviewed as a diff and exercised by `tst_emoji.qml`).
- Tests call `failOnWarning(/\.qml:\d+/)` in `init()`, so any QML runtime warning fails the suite. Test seams: `OverlayPopup.chimeEnabled`, `objectName: "card-<msgId>"` on overlay cards, `objectName: "textScaleCombo"`.
- A regression test carries a comment naming the bug it pins.
- The author identity is the `clearcmos` handle and `clear.cmos@outlook.com`. No real names anywhere else, apart from third-party license notices.

## Policies

- Coverage: no open-source coverage tool exists for QML/JS, so none is measured. Per-module test presence plus regression tests are the gate instead.
- Dependencies and updates: nothing is vendored except `Emoji.js` (regenerated deliberately from ntfy's `main` and reviewed as a diff) and the chime. Dependabot bumps the SHA-pinned GitHub Actions monthly. The CI container digest is bumped by hand; pacman upgrades to current packages at run time regardless.
- Changelog: git history is the changelog; there is no CHANGELOG.md. Bump `Version` in `package/metadata.json` when a release changes user-visible behavior.
- Distribution: clone and run `install.sh`. No KDE Store package.
- Third-party assets: `package/contents/sounds/power-plug.wav` is LGPL-3.0-or-later with its notice in `power-plug.wav.license` and the license text beside it. Anything else added from elsewhere gets the same treatment.

## Decision log

- 2026-07-22: The feed dedupes by ntfy message id, because every reconnect backfills `since=` history the feed already holds.
- 2026-07-22: Manual reconnects are throttled to one per 2 s. Aborting and reopening faster than the server notices the close leaks subscribers and can trip ntfy's visitor limit.
- 2026-09-22: Only messages newer than widget load reach the overlay (`startedSec`), so a plasmashell restart does not replay the backfill on screen.
- 2026-09-22: Overlay fades are explicit animations started 30 ms after a card is created (251574d), so the window is mapped and the whole fade is visible.
- 2026-09-23: The chime ships as WAV because `SoundEffect` only plays uncompressed audio. Upstream licenses it LGPL-3.0-or-later (per-file REUSE notice), not the LGPL-2.0-or-later Arch's package metadata states.
- 2026-09-23: `NtfyClient` consumes only complete lines (`Feed.completeLines`). The old parser advanced past a line split across two reads, so both halves failed to parse and the message was lost; the live test showed Qt's XHR does deliver such splits. Pinned by `tst_ntfyclient.qml` and `tst_ntfyclient_live.qml`.
- 2026-09-23: Lint runs through `scripts/lint-qml.sh` because Qt 6 qmllint exits 0 on warnings and cannot see Plasma's context-injected `i18n`. It reads qmllint's JSON report and allowlists only those names; `tests/test_lint_qml.sh` proves it rejects a bad file and fails when qmllint is missing.
- 2026-09-23: The overlay's cards live in a `ListModel`. A JS array property made the Repeater rebuild every card on each push or dismiss, replaying the fade-in of cards already on screen. Pinned by `test_existingCardsSurviveQueueChanges`.
- 2026-09-23: CI runs in an `archlinux:base` container because the Ubuntu runner images do not package the Plasma 6 QML modules the widget imports.
